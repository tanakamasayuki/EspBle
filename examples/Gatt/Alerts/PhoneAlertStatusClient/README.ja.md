# PhoneAlertStatusClient

> English: [README.md](README.md)
> 概念の説明: [BLE通信の入門ガイド](../../../../docs/GUIDE_BLE_BASICS.ja.md) 4章「GATT編 — データをやり取りする」

Phone Alert Status Service（0x180E）へ接続し、Alert StatusをRead、Ringer Settingを購読、Ringer Control Point（**Write Without Response**）でSilent Mode設定→解除を行い、NotifyされたRinger Settingを毎回表示します。

## 必要なもの

- 1 × ESP32-S3（このスケッチ。Central）
- 1 × Phone Alert Status Peripheral: [PhoneAlertStatusServer](../PhoneAlertStatusServer/) example

## 動作

- 0x180EをAdvertiseする機器をscanして接続
- Alert Status（0x2A3F）をReadしbitmaskを表示
- Ringer Setting（0x2A41）の**Notification**を購読
- 5秒ごとにRinger Control Point（0x2A40）をSet Silent Mode（1）とCancel Silent Mode（3）で切り替え、NotifyされたそれぞれのRinger Settingを表示

## 主なAPI

- `ble.writeCharacteristic(connectionId, service, characteristic, data, length, false)` — Write Without Response

## 期待されるSerial出力

```
Alert Status: 0x01
Ringer Setting: Silent
Ringer Setting: Normal
```

## コードを読む順序とAPI

次の項目はソース中で最初に登場する順です。コールバックの登録順は実行順ではありません。イベントが届いたときに、その関数が実行されます。

1. `ble.writeCharacteristic(...)` — 相手へのWriteをキューへ登録し、完了イベントを確認します。Write Without Responseには、相手アプリの処理を保証するATT応答はありません。
2. `ble.begin(...)` — 使用するスタック／プロファイルを初期化し、戻り値を確認してから後続処理を開始します。BLEのGATT Serverでは、スタック初期化前にデータベースを登録します。
3. `ble.onConnected(...)` — このイベントで接続成立を確認し、プロファイルに必要な相手／セッション情報を保存します。connect要求の受理はそれより前で、利用可能なリンクの成立を意味しません。
4. `ble.readCharacteristic(...)` — 相手の値のReadをキューへ登録します。値は即時のboolではなくonCharacteristicReadへ届きます。
5. `ble.onDisconnected(...)` — 利用可能フラグと保存した接続／セッション情報をここで解除します。古いIDを新しい相手に使わないようにし、スキャンや広告の再開はコードにある処理を確認します。
6. `ble.onCharacteristicRead(...)` — 成功・UUID・値の長さを確認してからデコードします。バイナリのStringには0バイトも含まれるので、長さを使って処理します。
7. `ble.subscribe(...)` — 相手のCharacteristic更新を購読します。NotifyとIndicateの購読方式を合わせ、購読の完了を待ちます。
8. `ble.onNotification(...)` — Characteristicと接続を絞り、バイナリ形式を検証してから更新をデコードします。IndicateのデータもこのAPIへ届きます。
9. `ble.scanner().onResult(...)` — 探索結果を確認してから相手を選びます。名前が含まれない場合があり、機器を発見しただけでは接続後の目的のサービスまで使えるとは限りません。
10. `ble.connect(...)` — 選んだ相手へ接続を要求します。接続イベントを待ってから、接続IDの利用やプロファイルの通信を始めます。

## 確認と変更のポイント

Alert Status・Ringer Setting・Ringer Control Pointは別の値です。制御書き込みで例の状態は変わりますが、電話サービスへ接続する機能ではありません。

`ble.update()` をloopで継続して呼びます。入力待ちや周期処理を長い待機で実装すると、キューの処理と次の通知が遅れます。

失敗を調べる際は「初期化→探索／公開→接続→必要なセキュリティ→探索／購読→値の通信」のどこまで進んだかを確認します。この例で使わない段階は省き、表示が少ないServer例は相手側のReadや通知受信で確認します。boolを返す要求では、その場の受理と後の完了イベントを区別します。すべての呼び出し結果を表示しない最小例をアプリへ組み込む際は、各戻り値と失敗時の処理も追加してください。
