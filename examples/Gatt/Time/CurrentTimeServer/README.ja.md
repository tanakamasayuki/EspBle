# CurrentTimeServer

> English: [README.md](README.md)
> 概念の説明: [BLE通信の入門ガイド](../../../../docs/GUIDE_BLE_BASICS.ja.md) 4章「GATT編 — データをやり取りする」

標準Current Time Service（0x1805）のPeripheral。Current Time（0x2A2B）はread/**notify**のCharacteristicで、10バイトの標準wire形式（year LE、month、day、hours、minutes、seconds、weekday、fraction256、adjust reason）を保持します。

## 必要なもの

- 1 × ESP32-S3（このスケッチ。Peripheral）
- 1 × Central: [CurrentTimeClient](../CurrentTimeClient/) example、または Current Time client

## 動作

- `begin()`の前にCurrent Timeを登録し、0x1805をAdvertise
- 固定のデモ時刻（2026-07-19 12:34:56、日曜、手動調整）で値を初期化
- Serialから`t`を送るとsecondsフィールドを1進め、値を設定して購読中のClientへNotify

## 主なAPI

- `ble.gattServer().setValue(...)` — 保持するCurrent Time値を更新
- `ble.gattServer().notify(...)` — 新しい時刻を購読者へNotify

## 期待されるSerial出力

```
Send 't' to advance one second and notify subscribers.
Time: 2026-07-19 12:34:57 (notification accepted: 1)
```

## コードを読む順序とAPI

次の項目はソース中で最初に登場する順です。コールバックの登録順は実行順ではありません。イベントが届いたときに、その関数が実行されます。

1. `server.setValue(...)` — ローカルに保持するCharacteristic値を変更します。これだけで購読中の相手へNotifyやIndicateが送られるわけではありません。
2. `server.notify(...)` — 購読者への更新をキューへ登録し、受理を確認します。Notifyには受信側からのATT確認応答がないため、必要に応じ送信結果やアプリの応答を使います。
3. `server.addService(...)` — BLEのbegin前にローカルServiceを作ります。Service UUIDはCharacteristicのまとまりを識別するもので、個体の識別子ではありません。
4. `server.addCharacteristic(...)` — BLEのbegin前に値と許可する操作を登録します。Read・Write・Notify・Indicateはそれぞれ別の能力です。
5. `ble.begin(...)` — 使用するスタック／プロファイルを初期化し、戻り値を確認してから後続処理を開始します。BLEのGATT Serverでは、スタック初期化前にデータベースを登録します。
6. `ble.advertising().addServiceUuid(...)` — Service UUIDで探すスキャナが発見できるよう広告へ含めます。UUIDを広告するだけではGATT Serviceは作られません。

## 確認と変更のポイント

Current Timeは日付と時刻の構造で、Unix秒ではありません。年月日・曜日・小数部・変更理由の整合性を保ちます。例はRTCや時刻同期源ではありません。

`ble.update()` をloopで継続して呼びます。入力待ちや周期処理を長い待機で実装すると、キューの処理と次の通知が遅れます。

失敗を調べる際は「初期化→探索／公開→接続→必要なセキュリティ→探索／購読→値の通信」のどこまで進んだかを確認します。この例で使わない段階は省き、表示が少ないServer例は相手側のReadや通知受信で確認します。boolを返す要求では、その場の受理と後の完了イベントを区別します。すべての呼び出し結果を表示しない最小例をアプリへ組み込む際は、各戻り値と失敗時の処理も追加してください。
